# 指标性能优化

本次改造保持秒级采集，将窗口统计放在 Go 探针中，Worker 按新增分钟保存摘要和公开投影。未调整重试策略。

## 上报协议

新探针采用 v6，服务端继续接受 v5 JSON/gzip。

v6 请求 Content-Type 为 `application/vnd.xugou.report+binary`，不使用外层 Content-Encoding：

```text
XG06 | 元数据长度 uint32 LE | UTF-8 JSON 元数据 | 按顺序排列的压缩块原始字节
```

元数据的块描述包含 `byte_length`，没有 Base64 `data`。本地 inflight 仍可用 Base64 持久化，已有 v5 inflight 按原协议发送。

- `minute_summaries`：本批每个原始分钟块的均值，保留缺失值和网卡计数器末值。
- `summary`：采集窗口边界、CPU/内存/磁盘峰值，以及逐网卡首末计数器和内部增量。
- 流量段按 UTC 日期与有效网卡拓扑变化拆分；月重置日与跨批基准仍由服务端核算。
- 完整归档校验移到读取端。v6 入库仍验证请求长度、协议版本、块头/维度/描述符边界、时间与摘要对应关系；v5 仍完整解码校验。
- v6 正常路径不解压归档。遇到升级时部分重叠的旧批次，保留完整计算作为兼容路径。

## 小时聚合与存储

探针不再每分钟重编码当前整小时；每次只发送新增分钟摘要，小时结束封存一次。封存以已处理采样水位为准，未封存累积器支持进程重启恢复。

完整小时原先累计编码 `1+2+...+60=1830` 个分钟点，新流程仅在封存时编码 60 点。这是该环节的数据处理量变化，不等于系统整体加速倍数。

迁移 `0054_nifty_ken_ellis.sql` 给现有 `agent_metric_blocks` 增加两列，没有增加指标表：

| 列 | 用途 |
| --- | --- |
| `summary_json` | 原始分钟行的均值摘要；封存小时行的完成标记及必要的升级兼容数据 |
| `public_json` | 小时行中按分钟槽更新的公开字段投影 |

未封存小时允许 `point_count=0`、空二进制的占位行，查询不会把它送入解码器。`byte_size` 包含二进制与摘要的 UTF-8 字节，热数据回收预算不会漏算新增摘要。

升级发生在小时中途时，旧、新块的点数不能代表时间槽覆盖关系。替换前仅在这一兼容路径合并已有块，保留新块未覆盖的旧分钟及其磁盘、网卡、ping 字段，避免旧前半小时或新后半小时丢失。

## 公开历史

状态发布只生成页面与最新状态，不再定时展开每台探针最近一天历史。

- `/api/v2/status/public/agents/{agentId}/metrics/manifest` 返回最多 25 个小时的小清单及各自版本。
- `/api/v2/status/public/agents/{agentId}/metrics/hours?buckets=...` 批量读取已准备好的小时块。
- `/api/v2/status/public/agents/{agentId}/metrics/hours/{bucketStart}` 处理单小时读取及旧归档的首次转换。
- 历史数据保持独立版本缓存；首次批量下载，后续只更新变化的小时。尚未转换的旧小时最多四个并行请求，避免一次调用集中解压整天旧数据。
- 浏览器在 Web Worker 中展开曲线；Worker 不可用时有功能回退。
- 匿名读取仍检查节点是否公开、隐藏或删除。公开投影使用固定字段白名单，不直接公开私有二进制归档。

## 管理端历史

管理端优先读取 `/api/v2/agents/{id}/metrics/blocks?hours=...`，沿用会话认证与原有时间窗口。响应为 `application/vnd.xugou.metrics+binary`：

```text
XHR1 | 元数据长度 uint32 LE | UTF-8 JSON 元数据 | 按顺序排列的归档原始字节
```

Worker 只读取有界索引窗口并传输归档、升级兼容样本及未封存分钟摘要，不解压归档。浏览器独立 Web Worker 复用同一 codec、字段映射和降采样逻辑，解码结果与原 JSON API 保持一致。页面切换或取消查询会终止下载与解码；浏览器不支持该能力时回退原接口。私有历史使用 `private, no-store`，不会进入公开缓存。

## 已删除的重复计算

- 未被摄入层使用的整包 JSON/SHA 摘要。
- 同一 Base64 块的第二次解码。
- 为计算 `point_count` 而创建全部样本对象；改为在解码时统计有效槽并集。
- 同一次更新中给相同权限范围的每位 WebSocket 订阅者重复序列化。

解码器对安全整数采用 Number 快路径，越界时回退 BigInt，保留原始 64 位差分语义。

## 本地验证与性能基准

```sh
pnpm run generate:contracts
pnpm run typecheck
pnpm run lint
pnpm run build
pnpm --dir backend test
pnpm --dir backend exec tsx --test \
  ../frontend/src/features/agents/history/decodeAgentMetricHistory.test.ts \
  ../frontend/src/features/agents/history/getAgentMetrics.test.ts \
  ../frontend/src/features/agents/history/workerClient.test.ts

cd agent
go test ./...
go build ./...
go test ./pkg/model ./pkg/spool ./pkg/reporter -race
go test ./pkg/reporter -run '^$' -bench . -benchmem
```

跨语言样本 `agent/pkg/reporter/testdata/report-v6.bin` 含跨月、网卡计数器归零、分钟摘要与封存块；后端测试验证正常 v6 摄入零解压、旧 v5 仍完整校验、阈值峰值及月流量。

在本次开发机上，固定四点样本的测量如下，仅用于对比指定环节。Go 编码取三次运行的中位数：

| 环节 | 旧路径 | 新路径 |
| --- | ---: | ---: |
| Go 请求编码 | 125.717 μs | 5.747 μs |
| Go 编码分配次数 | 30 | 8 |
| 后端请求解析与归档检查（均值） | 0.3058 ms | 0.0543 ms |

小样本请求体由 851 B 增至 3,266 B：增加摘要、去掉外层压缩存在带宽取舍。小时聚合不再反复发送，但不能据此宣称所有单次请求都更小。

这些是本地微基准，不含生产 D1、网络、冷启动和实际设备规模，不代表线上 CPU P99 已达到 5 ms。线上验收应同时记录 CPU、请求字节、D1 读写和浏览器冷首屏耗时。

## 上线顺序

先应用新增数据库迁移，再部署兼容 v5/v6 的后端与前端，最后发布和升级新探针。旧探针继续走兼容路径，摘要化摄入的主要收益需要新探针启用后才会出现。

上线验收以实际运行的探针版本、服务状态和 v6 成功上报记录为准。新探针启用后，回滚后端也应保留 v6 协议兼容能力。
